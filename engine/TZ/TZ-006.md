## 1.2 «⭐ Ставка дня» → два пункта (встроенные кнопки)
```
⭐ Ставка дня
[ 🔄 Ставки на сутки ] [ 🗂 История ]
```
### 🔄 Ставки на сутки — на случай, если чат был очищен
1. Заново присылаются **все** ставки дня текущих суток вида спорта: ⭐1…⭐N с текущими текстами, категорией (💰/🎯) и правками ✏️.
   Каждая ставка — отдельным закреплённым сообщением.
2. Если в чате уже есть такое же сообщение (та же ставка, тот же номер), **старое удаляется**, новое закрепляется. Дублей нет.
3. Реализация:
   - Apps Script запускает облако `football.yml` с параметром `inputs[resend_picks]=1` (dispatch_ уже есть);
   - облако (dpcore.resend_all): delete(старые msgs) → send_markup(текст) → pin → rt.day_pick.msgs обновлены;
   - сразу приходит ответ «⏳ Обновляю ставки дня — 1–2 минуты», после прихода ставок он удаляется.
4. Ставок в сутках нет — одно сообщение «Сегодня ставки дня нет: <причина>».

### 🗂 История — ставки дня за выбранную дату
1. Нажатие → одно сообщение-«экран» с выбором даты. Экран правится на месте (editMessageText), новых сообщений нет:
   - год (если в данных больше одного) → месяц → даты месяца, где были ставки дня;
   - кнопки по 7 дат в ряд, «◀ месяц ▶».
2. Выбор даты → все ставки дня этой даты: номер, линия, матч, P, честный кф, кф, категория 💰/🎯, итог ✅/❌/⚪, CLV, правки ✏️.
3. **Чтобы не мусорить:** при выборе ДРУГОЙ даты сообщения предыдущей даты удаляются, на экране только одна выбранная дата.
4. **Через 15 минут без нажатий** (пользователь перестал смотреть):
   - экран выбора и сообщения истории удаляются;
   - вместо них остаётся **одно сообщение** — «🗂 Ставки дня · ДД.ММ» за последнюю просмотренную дату.
   Реализация — триггер Apps Script раз в 5 мин, время последнего нажатия хранится в свойствах скрипта.
5. Данные — лист day_pick (итоговые версии) и dp_changes (правки). Apps Script читает сам, облако не нужно, ответ мгновенный.

## 1.4 «📊 Аналитика» — предложение (решение пользователя: «изучи все виды отчётов и сам предложи»)
### Что есть сейчас (изучено)
| Отчёт | Где формируется | Сейчас в «Аналитике» |
|---|---|---|
| ① Отчёт: исход, линии, тотал фикс., матчи с итогами | report.build (суточный / недельный) | «Всё время», «По месяцу», «По турниру» (лист reports) |
| ② Каперы: прогнозы, итоги, 🔥/⚔️, доверие ✔/⛔, CLV | caprep.report + tipsbook.card + selflearn.cap_block | нет |
| ③ Ставки дня: ⭐1, ➕, ✏️, 💰/🎯, ROI, CLV | report.dp_report + selflearn.day_block | нет (только «⭐ Вчера» в старом отчёте) |
| 🧠 Самообучение: уроки, правила, ступени | learning.report, selflearn | «🧠 Самообучение» |
| 🔎 Аудит: карточки недели | learning.audit_report | «🔎 Аудит» |

### Предлагаемая схема — одно сообщение-«экран» с навигацией
Каждый шаг правит то же сообщение. Как в 1.2, через 15 мин без нажатий экран схлопывается до последнего показанного отчёта.
```
📊 Аналитика
Шаг 1 — год:            [ 2026 ] [ 2027 ] …
Шаг 2 — раздел:         [ 📈 Отчёт ] [ 👥 Каперы ] [ ⭐ Ставки дня ]
                        [ 🧠 Самообучение ] [ 🔎 Аудит ] [ 🏆 По турнирам ]
Шаг 3 — срез:           [ 📅 День ] [ 🗓 Неделя ] [ 🗓 Месяц ] [ Σ Весь год ]
Шаг 4 — выбор:          День → месяц → дата; Неделя → «пн–вс» списком; Месяц → 12 кнопок
                        [ ◀ Назад ] на каждом шаге
```
| Раздел | День | Неделя | Месяц / год | Содержимое |
|---|---|---|---|---|
| 📈 Отчёт | ① суточный за дату | ① недельный пн–вс | таблица периода (без списка матчей — он длинный) | исход, линии по рынкам, тотал фикс., калибровка |
| 👥 Каперы | ② за дату | ② за неделю | по каналам: угадано, ROI, CLV, статус ✔/⛔ | итоги по независимому табло |
| ⭐ Ставки дня | ③ за дату (= История 1.2) | ③ за неделю | ⭐1 / ➕ / ✏️ / 💰 / 🎯: угадано, ROI, CLV | + «🧠 Аудит недели» в недельном срезе |
| 🧠 Самообучение | уроки этой даты | уроки недели | все действующие правила + история | lessons.json, лист learning (урок) |
| 🔎 Аудит | — | карточка недели | карточки месяца / года | лист learning (неделя) |
| 🏆 По турнирам | — | — | лига / турнир за период | как сейчас «По турниру» |

### Как реализовать
- **Готовые тексты кладёт облако в лист reports** с ключами `<раздел>:<срез>:<дата>`, например `dp:d:2026-11-14`,
  `rep:w:2026-11-09`, `cap:m:2026-11`, `learn:y:2026`:
  - суточные и недельные — при отправке отчётов, тем же текстом, что ушёл в чат;
  - месяц и год — пересчёт раз в сутки (11:37);
  - хранение: все дни и недели (≈ 3 раздела × 365 строк в год — в пределах листа).
- **Apps Script только строит экран** из ключей листа (какие годы, месяцы и даты есть) и отправляет текст. Облако на нажатие
  не запускается, ответ мгновенный, лимиты GitHub не тратятся.
- Нет отчёта за выбранный срез — «за этот период данных нет».
- Длинный отчёт режется по правилам доставки Д2 (теги не ломаются).
