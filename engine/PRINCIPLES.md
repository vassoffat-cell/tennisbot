# 📘 PRINCIPLES — как устроен «Standing in motion», от А до Я (26.11.2026)

Один документ, чтобы понять систему целиком: что она делает, из чего состоит, по каким правилам решает и **когда что происходит**.
Правила с номерами (Ц, В, Г, С, Л, К, О, Д, Р) — в `engine/CONTROL.md` (там же «как проверить»); карта файлов и текущее состояние — `engine/START.md`.
При расхождении документов главный — CONTROL (решения пользователя), затем код. Тайминг здесь сверен с кодом 26.11
(`.github/workflows/*.yml`, `apps_script/Code.gs`, `football/apps_script/Code.gs`, `config.py`, `football/caprun.py`).

## А. Цель
Выйти в плюс на ставках: больше угаданных линий и честный перевес по цене (EV, CLV). Девиз — бесконечное совершенство,
все бесплатные инструменты, не «невозможно», а расчёт и путь (Ц1). Число угаданных и ROI/CLV — равноправные меры (Ц1а).
Цифры честные: процент без цены — не заслуга (Ц2). Размер ставки и критерий остановки решает только пользователь (Ц10).

## Г. Модели
- **Теннис:** Elo (общий, покрытие, по геймам) + модель подачи/приёма → точная марковская цепь (гейм → тай-брейк → сет → матч);
  исход ATP — смесь с Pinnacle (A1). Точность 2023–26: WTA ≈ 66,6%, ATP ≈ 66,2%.
- **Футбол:** Dixon–Coles по странам (голы + удары в створ), сила стран по еврокубкам, календарь; 1X2 и Т2,5 — смесь с Pinnacle (A2).
- **Хоккей:** Пуассон с раздутием ничьих; НХЛ — линии из рынка (инверсия «победа + тотал», A21), пустые ворота (A22), гости второй день подряд (A11).
- **Рынок:** маржа снимается методом Шина; рынок точнее моделей — поэтому решения по деньгам опираются на цену (Ц10, IMPROVE).

## Д. Линии
Каждая линия — с вероятностью P и «честным кф» = 1/P (Л2). Показ P 0,50–0,80; тотал — фиксированная линия (ATP 22,5 · WTA 20,5 ·
bo5 35,5 · футбол 2,5 · НХЛ 4,5 · КХЛ 3,5; Л1/Л1а). Списки прогнозов не публикуются (В1) — линии живут в таблицах и отчётах.
Раз в сутки — самокалибровка k по рынкам; рынок с z ≤ −2 на 30 линиях — ⛔ выключается сам (и возвращается сам).

## Синтез — как сходятся все источники (Ц14)
Решение по каждой ⭐ — не голос одного источника, а сложение четырёх, в одном порядке для ⭐1, доп. 🎯, правки и снятия, во всех видах:
1. **Рынок + модель → справедливая P.** Pinnacle без маржи (Шин) — основа; модель добавляется с весом истории (теннис −0,11, футбол A2);
   хоккей — инверсия рынка НХЛ. Цена — лучшая контора; EV = (1 − P возврата)·(P·кф − 1).
2. **Порог:** P ≥ 0,60 (хоккей 0,55), кф ≥ 1,35, EV ≥ −3%; иначе кандидата нет.
3. **Каперы:** вето ✔ доказанного канала — кандидат исключён, объявленная ⭐ снимается; 🔥 канала ✔ или близкого к ✔ поднимает
   кандидата выше остальных 🎯, ⚔️ — опускает в конец. Слабый ⛔ канал не влияет.
4. **Самообучение:** пониженный сегмент (рынок, корзина P, 🔥/⚔️, новые линии — О2) уходит в конец и не становится ни новой ⭐, ни правкой;
   отключённые причины правок не работают (О4); запас для правки растёт при частых ошибках (О5).
**Итоговый порядок:** 💰 выгодная → 🎯 с 🔥 каперов → остальные 🎯 по EV → 🎯 с ⚔️ (самообучение — первым ключом: пониженные в конце).
Каперы по теннису за месяц не прогнозировали (0 из 628 постов) — в теннисе работают звенья 1, 2, 4; звено 3 включится само при первом прогнозе.

## Е. Ставка дня ⭐
1. **Сутки:** теннис и футбол 08:00 → 08:00, хоккей 12:00 → 12:00 (Р1). Первый приговор ⭐1 — после отчёта и самообучения (Р8): теннис и футбол 11:30, хоккей 12:30; отдельный закреп (С1, С3); матчи 08:00–11:30 без ⭐.
2. **Цена:** лучшая цена среди контор (С25а); справедливая P — Pinnacle без маржи (+ модель с малым весом).
3. **Лестница (С23):** 💰 «выгодная» — цена выше справедливой на 3–20%, П1/П2, кф 1,70–2,50 (теннис), ставка 1 ед., без лимита;
   иначе 🎯 «уверенная» — максимальный EV среди P ≥ 0,60, кф ≥ 1,35, EV ≥ −3%, ставка ¼ ед.; **до 3 🎯 в сутки на вид** (С23а),
   каждая — свой матч; матчи могут идти одновременно (С14 отменено 26.11). Хоккей — только линии с ценой основного времени, P ≥ 0,55 (С26, С26а).
4. **EV** = (1 − P возврата)·(P·кф − 1) — честно для целых линий (исправлено 21.11). EV > 20% — сначала проверка данных.
4а. **Как появляются ⭐2, ⭐3 …** (dpcore шаг 2b, hockey/hpick — то же). На КАЖДОМ прогоне суток — утреннем, резервном, по плану матча
   (T−3 ч, T−40 мин) и внеплановом после свежей ставки капера — система заново собирает кандидатов: каждая линия каждого ещё не
   начавшегося матча суток, у которой есть цена конторы, получает справедливую P (Pinnacle без маржи) и EV по лучшей цене.
   Отсев: P ≥ 0,60 (хоккей 0,55), кф ≥ 1,35, EV ≥ −3%, нет вето ✔ капера, матч не начался; 🔥 близкого к ✔ канала поднимает кандидата,
   ⚔️ — опускает (Г3б). Дальше:
   - **💰 выгодная** (цена выше справедливой на 3–20%, П1/П2, кф 1,70–2,50; сейчас — теннис): каждая такая линия другого матча сразу
     становится новой ⭐ — без лимита;
   - **🎯 уверенная:** кандидаты идут в порядке синтеза (самообучение → 🔥 → EV → ⚔️, см. «Синтез»); лучший из тех, чей матч ещё не занят ⭐
     (одновременные матчи — можно, С14 отменено 26.11), становится новой ⭐ — пока 🎯 в сутках меньше 3. Снятая ⭐ (С2а) место освобождает;
   - новая ⭐ — отдельное закреплённое сообщение «⚽2 Футбол · ставка дня · 🎯 уверенная» со строкой «➕ новая линия дня в ЧЧ:ММ:
     EV +x% · 2-я 🎯 из 3», строка в day_pick и dp_changes «новая: …»; прежние ⭐ не меняются.
   Поэтому ⭐2/⭐3 появляются днём: утром у многих вечерних матчей ещё нет цены, она приходит в прогоне за 3 ч до матча. Не хватает
   кандидатов, прошедших отсев, — ⭐ меньше трёх; это не сбой.
5. **Перепроверка** перед каждым матчем (T−3 ч, T−40 мин): лучшая линия того же матча → «✏️ мнение изменилось» (С2); ⭐ ниже порога
   при свежей цене → правка или «❌ снята — рынок против» (С2а). После начала матча ⭐ заперта (С20).
6. **Каперы в выборе:** ✔ доказанный канал — вето и снятие; близкий к ✔ (n ≥ 50, z ≥ 1,0, ROI > 0) — 🔥 поднимает, ⚔️ опускает (Г3а, Г3б).
7. **Честность:** утренняя ⭐1 несёт строку «🔎 Сутки … · 🔏 код» — снимок всех линий в репозитории до матчей (С16); каждый промах ⭐ —
   🔴 инцидент с причиной (Ц12); теневой портфель — каждая сторона с ценой как бумажная ставка (С21, С21а, С21б); банк в отчёте ③ (С27).

## Ж. Каперы
1. **Сбор:** каналы читаются каждый час в :22 с 15:22 до 02:22; 03:00–15:00 — тихое окно, посты окна приходят в 15:22 (Г0б).
   Страховка capTick: нет прогона > 62 мин (вне окна) → запуск. Перерыв ≤ 75 мин (Г0).
2. **Разбор:** текст и картинки всех 5 каналов (OCR, 23.11); купоны 1WIN и 1xBet/Melbet, экспрессы — каждая нога отдельно (24.11);
   открытый купон («Продать за», «Возможный выигрыш», «Принята») — прогноз до матча; непонятный пост не теряется — «❔ ставка не разобрана» (К9).
   Не прогнозы: отзывы, отчёты о выигрыше, рассчитанные купоны («выплачена»), реакции на итог («СТАВКА - 🔴🔴»), посты-статистика.
3. **Сообщение:** КАЖДЫЙ прогноз — отдельным сообщением: канал (ROI) · вид · матч · ставка @кф · ⏰ время матча · вердикт (Г0, Г2а, К8).
4. **Вердикт (К15–К17):** наш матч — та же P, что у ⭐ (рынок + модель, 24.11; без цен — модель): 🔥 согласна / ⚔️ против / · нейтральна;
   хоккей НХЛ — P ⭐ (Pinnacle), КХЛ — модель; другая лига с ценой DraftKings — рынок (P);
   таймы — по Пуассону таймов; ⬜ — только фолы/угловые, лига без цен, вид спорта вне модели (единоборства), матч не найден; пост после начала и «LIVE» — 🔴.
5. **Журналы:** книга каналов (book.csv), сверка книги с табло (book_ind.csv), «все матчи» (tips_all.csv), каперы × наши матчи
   (tips.csv), счета таймов (halves.json). Итог — только независимый (по табло), не отметка канала (К13).
6. **Доверие (самообучение):** ✔ доказан (z ≥ 1,64) — вето; ⛔ слабый — не учитывается; близкий к ✔ — мягкое влияние (Г3б).
7. **Свежая ставка капера** запускает внеплановый прогон её вида (≤ 8 в сутки, К2).

## З. Отчёты (форматы закреплены — REPORT_STYLE §9)
Суточный — три сообщения на вид: ① «📈 отчёт» (сутки / неделя / всего, матчи с итогами линий), ② «👥 каперы» (все каналы, итоги, ROI,
🧠 обучение на каперах), ③ «ставки дня» (угадано, ROI, CLV, банк, правки, снятые ⭐, 🔴 инциденты, 🧠 обучение). Понедельник —
те же три за неделю + «🧠 Аудит недели». Без легенд и подсказок, ширина таблиц ≤ 35 знаков (В7, REPORT_STYLE).
Сутки без матчей тенниса — тихий режим, без пустых отчётов (С18). Архив отчётов — меню ботов (ТЗ-006).
**Вид (В9, 27.11):** ①②③ и закрепы ⭐ — картинками (светлый фон, hi-tech минимализм, Montserrat; cards.py), в недельном ③ — график банка,
свёрнутые списки, прогнозы каперов и 🔒 — текстом; меню «Аналитика / История» — те же картинки (file_id в archive). **Формат улучшается
постоянно (Ц17):** каждый аудит — разбор вида недели и ≥ 1 улучшение с образцом; ошибки вида — сразу.

## И. Самообучение (после каждого суточного отчёта)
selflearn: сегменты своих ставок (понижен / сильный — по итогам и CLV), правки по причинам, лимит ставок, каперы ✔/⛔, общий сдвиг P,
инциденты промахов ⭐. Уроки → лист learning и lessons.json трёх видов; действуют со следующего выбора ⭐ (О1–О9).
Цена закрытия (CLV): Betfair из файлов или последний снимок цены до начала матча; хоккей — DraftKings + инверсия.

## К. Контроль и аудит
- **health.py** — здоровье без чтения логов: прогоны, опоздания, 🔒, каперы (перерыв, «не присланы 0», «потеряно 0»), журналы
  (сторож на каждый — «тихая пустота = сбой», CODEX 2а), теневой портфель, печать С16, лимиты API.
- **Еженедельный аудит** (пн 15:00, задача Claude): эталон (CONTROL §0) → каждая строка реестра по колонке «Проверка» (0а) → журнал
  ошибок (0б) → честность снимков (0в) → 🔒 и скрытость (0г) → порядок документов (0д) → каждый инцидент ⭐ «5 почему» (0е) → каперы и
  тихая пустота (0ж) → калибровка, качество, развитие (≥ 3 скрытых среза, ≥ 1 идея, глобальный вопрос). Итог — карточка «📅 Аудит»
  в ботах и запись в HANDOFF для «Разработчика». Не состоялся — проводит «Разработчик» (Д7).
- **Проверки «Разработчика»** — разовые задачи Claude по датам (CONTROL «Календарь проверок»).

## Л. Доставка и скрытность
Повтор при сбоях, нарезка длинных сообщений, очередь недоставленного (повтор каждым прогоном, до 12 попыток) — Д1–Д6.
Все сообщения — скрытым текстом Telegram (spoiler): в чате и списке чатов точки (В3б): таблицы `<pre>` — простым текстом, тоже скрыты; ответы меню — скрыты (Code.gs, 23.11).
Последнее сообщение каждого прогона — тихая контрольная точка «🔒 ЧЧ:ММ · … проверка ✓ · далее ЧЧ:ММ» (В3а).

## М. Лимиты и экономия
GitHub ≈ 2 000 мин в месяц у private (Ц19, 27.11: аудит, саморазвитие и развитие — без экономии; минуты на исходе → public до 1-го, затем private; плановые ≤ 60 мин в сутки): шлюз — плановый прогон пропускается, если полный прогон того же бота был < 35 мин
назад (Ц7); облако из чата — для проверок и исследований без экономии (Ц19). API-Sports ≤ 90/сутки, The Odds API 500/мес по долям, OddsPapi 250/мес (учёт каждого запроса, резерв тенниса — Ц6б),
Google Таблицы ≤ 60 чтений в минуту (повтор при 429/5xx). Платное — никогда (Ц6).

## П. Как вносится изменение (ORG.md §2, Ц16)
Исправление (код расходится с принятым правилом) — быстрая дорога: тест регрессии (`cd football && python3 test_regress.py`, 47 проверок) →
проверка в условиях облака → push → прогон → health → доклад. Новая логика — полная: карточка → проверка → независимый PASS → «давай» →
включение на одном виде с откатом. Затем строка в CONTROL, документы (репозиторий + проект); ошибка — журнал CONTROL §3.
