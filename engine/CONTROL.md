# 🎛 Контроль проекта — реестр замечаний пользователя, контрольные точки, журнал ошибок

**Зачем (решение пользователя 14.11.2026):** «все замечания и контрольные точки задокументируй, чтобы каждый раз не тратить кредиты».
Любой чат или облачная задача начинает работу с ЭТОГО файла вместо перечитывания чата и логов:
1. `python3 engine/health.py 26` — здоровье за сутки (только GitHub API, без скачивания всех логов);
2. раздел «Контрольные точки» — что должно было случиться и где проверить;
3. раздел «Реестр замечаний» — правила, которые нельзя нарушить никаким изменением;
4. новое замечание пользователя — сразу строкой в реестр (дата, суть, где реализовано, как проверить), затем код.
Подробности по темам — STATUS.md (что сделано), AUTOPILOT.md (гипотезы), IMPROVE.md (проверки), REPORT_STYLE.md (вид сообщений),
AUDIT.md (еженедельный аудит). Этот файл — короткий указатель «что должно быть правдой».

## 4. Как работать дёшево (порядок для любого чата и задачи)
1. `python3 engine/health.py 26` → таблица ✅/❌. Всё ✅ — к задаче; ❌ — сначала чинить, строка в раздел 3.
2. Нужен лог — только конкретного прогона: `gh run view <id> --log | grep -E "ставка дня|отчёт|сбой|🏒"`. Не качать все логи.
3. Нужны данные — лист Google (day_pick, dp_changes, hk_day_pick, hk_games) точечным диапазоном.
4. После изменения: офлайн-тест → push → ОДИН облачный прогон → `health.py 2`.
5. Новое замечание пользователя — строкой в раздел 1 этого файла в том же коммите.
