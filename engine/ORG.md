## 2. Путь изменения — две дороги
**Быстрая дорога — исправление** (код расходится с уже принятым правилом CONTROL/START, сбой, потеря данных). Решение пользователя
не нужно, ждать понедельника не нужно:
1. случай сбоя → тест регрессии (вход из реальных данных, ожидаемый результат);
2. исправление → офлайн-тест + все тесты регрессии (`cd football && python3 test_regress.py`, новый случай — в тот же коммит);
3. проверка **в условиях облака** (sparse checkout, переменные окружения, реальные файлы данных) — урок 21.11 «Alcaraz»;
4. push → один облачный прогон → health;
5. доклад пользователю — **только после шага 4**, с фактом из лога; строка в журнал CONTROL §3.

**Полная дорога — новая логика** (новое правило, порог, рынок, источник, модель, расписание, архитектура):
1. **07 карточка:** проблема (данные: n, z, ссылка на health/аудит) · ожидаемый эффект (точность, CLV, минуты, квоты) · риск и откат ·
   критерий успеха;
2. **08 проверка:** история без утечки, теневой портфель, чек-лист крайних случаев (ниже), расход минут и квот;
3. **09 независимый вердикт PASS / REWORK** — не автор изменения: отдельный агент или аудит;
4. **решение пользователя:** «давай» в чате или по итогу аудита пн 15:00;
5. **канарейка:** включение на одном виде или рынке через флаг, прошлая версия в резерве, откат при ❌ health; затем полное включение,
   старые следы — в том же коммите (Ц15); строка в CONTROL §1.

**Чек-лист крайних случаев (08):** нет цены (NO_ODDS) · возврат на целой линии · перенос или отмена матча · LIVE · тихое окно
каперов 03–15 · нечитаемый купон · шлюз 35 мин · межсезонье тенниса (С18) · 429/5xx Google и API · вывод за лимиты (минуты 2 000/мес,
Odds API 500, OddsPapi 250, API-Sports 90/сутки, Sheets 60/мин).
